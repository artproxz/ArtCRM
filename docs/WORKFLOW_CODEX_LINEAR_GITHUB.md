# Регламент работы: пользователь — ChatGPT — Codex

## Роли

### Пользователь

Владелец продукта и связующее звено. Передаёт бизнес-замечания, выполняет финальную ручную проверку интерфейса и подтверждает приёмку.

### ChatGPT

Архитектор и ревьюер. Отвечает за архитектуру, критерии приёмки, проверку Linear-задач, GitHub diff, commits, PR, тестов, CHANGELOG и профильной документации. Работа не принимается по одному текстовому отчёту Codex. Даже мелкие несоответствия фиксируются как замечания или запрос изменений.

### Codex

Разработчик. Читает актуальные задачи в Linear, рабочую документацию и код. Реализует изменения профессионально и минимально, не выходит за scope, добавляет тесты, выполняет запуск и UI-smoke, делает commits, push и PR. Не пишет «готово», если критерий не проверен фактически.

## Источники истины

### Linear

Источник задач, критериев приёмки, зависимостей, статусов и рабочих комментариев. Технические детали и найденные отклонения фиксируются в соответствующей задаче.

### GitHub

Источник кода и доказательств выполнения: ветки, commits, diff, PR, review comments, CHANGELOG и профильная документация.

### Локальная среда

Источник фактического запуска и UI-smoke. Результаты должны быть зафиксированы в Linear и PR конкретными командами и фактическими результатами.

## Текущая область

Работаем только с тендерным модулем ArtCRM: тендерный дашборд, карточки, вкладки, unread, уведомления, позиции, TenderPro, этапы торгов, связанные API и тесты. Другие модули CRM и старые проекты не затрагивать.

## Цикл задачи

1. Codex читает CODEX_WORKING_PRINCIPLES.md, CODEX_CONTEXT.md, этот регламент и актуальную Linear-задачу.
2. Проверяет git status, remote и рабочую ветку. Не использует reset --hard, git clean или force push.
3. Переводит задачу в In Progress и пишет комментарий с веткой.
4. Реализует только описанный scope и добавляет targeted tests.
5. Делает отдельный понятный commit и обновляет CHANGELOG.md; для крупной задачи обновляет профильную документацию.
6. После реализации создаёт или обновляет PR и переводит задачу в In Review/Testing, но не в Done до финальной приёмки.
7. ChatGPT проверяет diff, тесты, архитектуру и соответствие критериям. При любом дефекте запрашивает изменения.
8. Пользователь выполняет финальную ручную проверку интерфейса и подтверждает приёмку.
9. Только после подтверждения работа переводится в Done и PR сливается.

## Отчёт Codex

В Linear и PR фиксировать: что изменено, причину ошибки, изменённые файлы, commits, команды и количество тестов, результаты API/UI-smoke, ограничения и всё непроверенное. Не подменять доказательства общими формулировками.

## Ревью

Приоритет — корректность, безопасность, отсутствие регрессий и соответствие архитектуре. Тесты сами по себе не доказывают готовность. Frontend-хак не принимается, если проблема должна решаться в backend или общей модели данных. Не допускаются расхождения между API, БД и UI, ложные счётчики, неявные fallback, дублирование данных, случайные изменения вне тендерного модуля и неполная документация.
